# bench

The comparison harness for Droid, Amp, and Claude Code on the Frontier task set.
Three JSON registries and three scripts. Adding a harness, a model, or an effort
level is a data edit plus a test, never a change to the matrix code.

## Files

| Path | Role |
|---|---|
| `config/harnesses.json` | One row per harness: how it takes a model id, its concurrency cap, whether it needs the identity shim. |
| `config/models.json` | One row per model variant. The key is `<transport>/<endpoint>/<model>-<effort>`; two rows that share a `base` differ in model or effort. |
| `config/tasks.json` | Generated by `calibrate.py`. Measured p50/p90 per model base, reward band, tier, and whether the task still discriminates. Do not hand-edit. |
| `config/builds.json` | Generated by `screen.py`. Whether the task's own Dockerfile builds. |
| `calibrate.py` | Re-measures every task from finished trials and rewrites `tasks.json`. |
| `screen.py` | Builds each candidate task in Docker before any agent time is spent on it. |
| `report.py` | Per-cell table plus a paired harness verdict that applies the pre-registered rule. |
| `plan.py` | Turns a selection into a `run_matrix.sh` call, enforcing the narrowest concurrency cap across the selected harnesses and model rows, plus route support. |
| `rerun_errors.py` | Reruns errored or over-budget trials in the newest job per harness and model, then replaces each stale trial in place. `--job <name>` fixes one job. |

A row may carry `max_concurrency`. The two swe-2 rows set it to 2 because
Devin's guide caps swe-2 at two concurrent calls; `run_matrix.sh` and `plan.py`
take the narrowest cap across the selected harnesses and rows.

A model reachable through more than one endpoint gets one row per endpoint, all
sharing a `base`. Haiku 5.5 is `9r/dv-bridge/haiku-5-5-max` for Droid, through
the Devin bridge, which is its only route: Droid's own catalog has no Haiku 5.5
and Factory inference answers 402 `no_active_subscription`. Devin refused every
trial of that row while the weekly quota was exhausted; the row is enabled again
now that the quota has recovered. `native/amp/haiku-5-5-max` is Amp, through its own Claude
access, and `native/claude/haiku-5-5-max` is Claude Code, through its own
Anthropic subscription token with no shim and no 9Router. `run_matrix.sh` asks
the registry whether a harness may run a row (`model_id.py <id> supports
<harness>`) and skips the pair when the answer is no.

`run_matrix.sh` also runs `model_id.py check` before the first job. It exits
non-zero when an id does not match its stored fields, a transport or harness is
unknown, or a route+effort pair appears twice. Job folders use `bench.lib.slug`,
which replaces `/` with `-`; the slash id never becomes a path.

The `route` field is the endpoint's own identifier (`devin/...`, `engy/...`,
`cx/...`) and the registry does not rewrite it. The id adds the transport and
endpoint around that route, so 9Router and the Devin bridge keep their names.

## The gate

A task must also build. `screen.py` runs `docker build` with the task's own
Dockerfile and records the result in `builds.json`; `plan.py` will not select a
task that failed it.

A task is in the `fast` tier when its worst measured p90 is at or under
`--gate-minutes` (default 20.0). Worst case is taken over model bases, because a
max-thinking model can spend longer on a reasoning task than a smaller one. Timed
out trials are excluded from the percentiles, since their duration measures the
budget that stopped them rather than the task.

A task `discriminates` when at least one model base scores strictly between 0 and
1. A saturated task stays in the pool for smoke tests but carries no information
about which harness or model is better.

## The decision rule

Written down before the run, applied by `report.py`:

- A winner needs six or more discordant tasks in one direction, or a matched gap
  of at least 0.10.
- Fewer than three shared tasks returns `insufficient` regardless of the gap.
- Anything else reports a tie and is broken on measured latency.

## Daily use

```bash
.venv/bin/python bench/calibrate.py
.venv/bin/python bench/report.py --pair droid,amp
.venv/bin/python bench/plan.py --models 9r/dv-bridge/swe-2-max --attempts 3 --tier fast
.venv/bin/python bench/plan.py --models 9r/dv-bridge/swe-2-max --attempts 3 --tier fast --execute
```

`report.py` reads `jobs/` directly, so a report never needs a rerun. `plan.py`
prints the command by default and only runs it with `--execute`.
